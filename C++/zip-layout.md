# ข้างในไฟล์ zip หน้าตาเป็นยังไง (2026-11-17)

- ไฟล์ทุกไฟล์คือ byte เรียงต่อกันเป็นแถวเดียว นับช่องจาก 0 ในไฟล์ไม่มีป้ายบอกว่าช่องไหนคืออะไร
- ไฟล์ txt: ทั้งแถวคือข้อความ ไม่มีอย่างอื่น
- ไฟล์ zip: มีกฎตกลงกันไว้ว่าช่องไหนเก็บอะไร เหมือนแบบฟอร์มที่ช่องกรอกอยู่ที่เดิมทุกครั้ง อะไรที่ยาวไม่เท่ากันทุกไฟล์ (เช่นชื่อไฟล์) จะมีช่องบอกความยาวไว้ก่อนเสมอ

ตัวอย่างจาก `III_ByteDump/hi2.zip` ไฟล์ยาว 110 byte ข้างในมีไฟล์ hi.txt ที่เขียนว่า `ha`

```
ช่อง  byte                 แบบฟอร์มบอกว่า
0–3   50 4B 03 04          ป้าย "PK" = ไฟล์นี้คือ zip
4–13  14 00 ... 6B 5D      version, วันที่ ฯลฯ ข้อมูลจิปาถะ
14–17 9E A2 48 D6          CRC
18–21 02 00 00 00          ขนาดใน zip = 2 byte
22–25 02 00 00 00          ขนาดจริงก่อนบีบ = 2 byte
26–27 06 00                ชื่อไฟล์ยาว 6 ตัว
28–29 00 00                ข้อมูลเพิ่มเติม ยาว 0
30–35 68 69 2E 74 78 74    ชื่อไฟล์ "hi.txt"
36–37 68 61                ข้อความในไฟล์ "ha"
38–   50 4B 01 02 ...      สารบัญรายชื่อไฟล์ แล้วจบด้วย 50 4B 05 06
```

ตัวเลขที่ยาวหลาย byte ใน zip เขียนกลับด้าน คือเอาหลักเล็กไว้ก่อน `02 00 00 00` เลยอ่านว่า 2
